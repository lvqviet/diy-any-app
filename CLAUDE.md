# DIY Any App

Personal macOS menu bar app (Swift/SwiftUI) that rebuilds features of paid apps in one native app.
Owner: lvqviet. Repo: `git@github.com:lvqviet/diy-any-app.git` (private, branch `master`).

`README.md` is the user-facing reference: features, architecture table, SMC keys, build/install,
helper debugging. Read it before changing battery behavior. This file covers what README does not.

## Purpose and direction

- Goal: replace paid utilities with features the owner actually uses, one feature at a time.
- Shipped: **Battery** (AlDente-style): Charge Limiter, Discharge, Automatic Discharge, Top Up,
  Sailing Mode, power and health readout. Released as 1.0.x and considered stable.
- Next features: not decided yet. Ask the owner which app/feature comes next; do not guess.
- A new feature gets a case in `MainWindow.Feature` (sidebar entry + page). Keep each feature's
  core logic in a testable package like `Packages/BatteryCore`, and its UI in `App/Views/`.

## Layout

| Path | Role |
| --- | --- |
| `App/DIYAnyApp.swift` | Entry point: `MenuBarExtra` (`.window` style) + `Window` with id `MainWindow.id` |
| `App/BatteryModel.swift` | `@Observable` app state: settings in UserDefaults, polls the helper over XPC |
| `App/HelperClient.swift` | `SMAppService` registration and XPC calls to the helper |
| `App/PowerSourceMonitor.swift` | macOS power source notifications, triggers an immediate refresh |
| `App/Views/` | `MenuBarPanel` (compact), `MainWindow` (sidebar + form), shared `BatteryControls`, `BatterySettingsRows` (window only), `BatteryRing`, `BatteryStyle`, `WindowVisibility` |
| `Helper/Sources/` | Root launchd daemon: `ChargeController` (5 s control loop), `XPCServer`, `PowerWatcher` (sleep/wake), `DebugCLI` |
| `Packages/BatteryCore/` | SMC client, `BatteryReader`, pure `ChargePolicy.decide`, `FailSafe`, XPC protocol. All unit tests live here |
| `scripts/` | `install.sh` (Release build into /Applications), `dev-helper.sh` (helper CLI as root), `make-app-icon.swift` |

`DIYAnyApp.xcodeproj` is generated by XcodeGen from `project.yml` and not committed.

## Commands

```sh
cd Packages/BatteryCore && swift test        # unit tests
xcodegen generate --quiet && xcodebuild -project DIYAnyApp.xcodeproj -scheme DIYAnyApp \
  -configuration Debug -derivedDataPath build/DerivedData -allowProvisioningUpdates build
scripts/install.sh                            # quits the app, installs Release, relaunches
```

## Design decisions to keep

- Only the helper writes SMC keys. The app never touches hardware.
- Charge control applies only while the app runs. App quit, crash or disconnect restores normal
  charging. 3 failed control-loop ticks in a row also restore it (`FailSafe`).
- Below the limit the Mac does not charge during sleep. This is intentional; the owner chose to
  keep it.
- Sailing Mode gap is fixed at 5% (`ChargeSettings.sailingGap`). It is a toggle, not a setting.
- The panel keeps the limit slider and the Discharge/Top Up buttons. The main window shows the
  limit as a numeric field, with Automatic Discharge and Sailing Mode as icon rows.
- Health shows two values: Apple's Maximum Capacity (from `system_profiler`, refreshed every
  10 min) and raw capacity in mAh.

## Performance rules (idle CPU must stay below ~1%)

- Closed `MenuBarExtra` panels and windows stay alive. A repeating animation in them renders
  every display frame (this once cost ~30% CPU). Gate repeating effects with
  `onWindowVisibilityChange`, as the charging pulse in `BatteryControls` does.
- Helper polling: every 3 s while a window is visible, 15 s otherwise. Power source
  notifications refresh immediately. Refreshes are coalesced, so never call `poll()` directly;
  use `refresh()`.
- Do not add per-poll system calls such as app lists or registration checks; use notifications.
- After changes that affect idle work, measure with
  `top -l 7 -s 5 -stats pid,command,cpu,idlew,mem -pid <pid>` while all windows are closed.

## Workflow

- Ask the owner when something is unclear; do not invent behavior or values.
- Window screenshots do not work here (`screencapture -l` fails). After UI changes, build,
  run `scripts/install.sh` and ask the owner to check visually.
- Commit after each finished change. Push only when the owner asks.
- Release: bump `MARKETING_VERSION` in `project.yml`, commit `Release x.y.z`, create the
  annotated tag `vx.y.z`, then push `master` and the tag when asked. The build number comes
  from the git commit count in `install.sh`.
- Bump `HelperConstants.protocolVersion` when the XPC interface changes.
